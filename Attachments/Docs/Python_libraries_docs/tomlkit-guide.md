# tomlkit — Complete Usage Guide

`tomlkit` is a **style-preserving** TOML library for Python. Unlike `tomllib`/`toml`, it keeps
comments, whitespace, key order, quote style, and array layout intact through a
parse → modify → dump round trip. That makes it the right tool for editing config files people
own (`pyproject.toml`, `config.toml`) rather than for plain data loading.

- **Install:** `pip install tomlkit`
- **Import:** `import tomlkit`
- **Verified against:** tomlkit 0.15.x, Python 3.9+
- **Spec:** TOML v1.0.0

## 1. Most Common Functions (start here)

These nine cover the overwhelming majority of real usage. Everything later in this guide is
detail on top of them.

| Function | Purpose |
|---|---|
| `tomlkit.parse(str \| bytes)` | Parse TOML text into a `TOMLDocument` |
| `tomlkit.loads(str \| bytes)` | Alias of `parse` (mirrors `json.loads`) |
| `tomlkit.load(fp)` | Parse from an open file object |
| `tomlkit.dumps(data, sort_keys=False)` | Serialize a document/dict/Mapping back to a string |
| `tomlkit.dump(data, fp, *, sort_keys=False)` | Serialize straight into an open file |
| `tomlkit.document()` | Create an empty `TOMLDocument` |
| `tomlkit.table()` | Create a `[section]` table |
| `tomlkit.comment(str)` | Create a standalone `# comment` line |
| `doc.unwrap()` | Convert the document to plain Python types |

**Description.** The canonical workflow is *parse → mutate like a dict → dump*. A `TOMLDocument`
is a real `dict` subclass, so ordinary dict syntax works on it; the formatting is carried along
invisibly in the item objects.

**Example — the 90% case:**

```python
import tomlkit

with open("pyproject.toml") as f:
    doc = tomlkit.load(f)

doc["project"]["version"] = "2.0.0"          # edit like a dict

with open("pyproject.toml", "w") as f:
    tomlkit.dump(doc, f)                      # comments and layout survive
```

**Example — build from nothing:**

```python
import tomlkit
from tomlkit import comment, document, nl, table

doc = document()
doc.add(comment("Generated by build.py"))
doc.add(nl())
doc.add("name", "app")

owner = table()
owner.add("org", "ACME")
doc.add("owner", owner)

print(tomlkit.dumps(doc))
```

```toml
# Generated by build.py

name = "app"

[owner]
org = "ACME"
```

## 2. Reading & Parsing

**Description.** Three entry points, all returning a `TOMLDocument`. `parse` and `loads` take
text or bytes; `load` takes an open file handle (text or binary mode). Parsing preserves
everything — trailing comments, blank lines, quote style, hex/octal literals, array line breaks.
Invalid input raises a subclass of `ParseError` carrying `.line` and `.col`.

| Function | Input | Returns |
|---|---|---|
| `parse(string)` | `str` or `bytes` | `TOMLDocument` |
| `loads(string)` | `str` or `bytes` | `TOMLDocument` (same as `parse`) |
| `load(fp)` | `IO[str]` or `IO[bytes]` | `TOMLDocument` |

**Example:**

```python
import tomlkit

src = """# top comment
title = "TOML Example"   # trailing

[owner]
name = "Tom"
dob = 1979-05-27T07:32:00-08:00
"""

doc = tomlkit.parse(src)

assert tomlkit.dumps(doc) == src          # byte-for-byte round trip
print(doc["owner"]["dob"].year)           # 1979 — real datetime behaviour

with open("config.toml", encoding="utf-8") as f:
    doc2 = tomlkit.load(f)
```

## 3. Writing & Serializing

**Description.** `dumps` returns a string, `dump` writes to a file object. Both accept any
`Mapping` — a `TOMLDocument`, a `Table`, or a plain `dict`. When given a plain dict, tomlkit
generates default formatting; when given a parsed document, it reproduces the original layout.
`sort_keys=True` sorts keys alphabetically at every level (and discards the original ordering).
`Container.as_string()` is the method form of `dumps` for a document you already hold.

| Call | Effect |
|---|---|
| `dumps(data, sort_keys=False)` | → `str` |
| `dump(data, fp, *, sort_keys=False)` | writes to `fp`, returns `None` |
| `doc.as_string()` | → `str`, equivalent to `dumps(doc)` |

**Example:**

```python
import tomlkit

# From a plain dict — tomlkit picks sensible default formatting
print(tomlkit.dumps({"b": 1, "a": 2}, sort_keys=True))
# a = 2
# b = 1

doc = tomlkit.parse("a = 1 # keep me\n")
doc["b"] = 2

print(doc.as_string())
# a = 1 # keep me
# b = 2

with open("out.toml", "w", encoding="utf-8") as f:
    tomlkit.dump(doc, f)
```

## 4. Accessing Values

**Description.** Reading is plain dict access. The values you get back are *item* objects that
subclass their Python counterparts (`String(str)`, `Integer(int)`, `DateTime(datetime)`,
`Array(list)`, `Table(dict)`), so they compare, format, and behave like normal Python values
while still carrying formatting metadata. Use `unwrap()` when you need genuinely plain types
(e.g. before `json.dumps`), and `item(key)` when you need the wrapper itself rather than the value.

| Accessor | Returns |
|---|---|
| `doc["key"]`, `doc.get("key", default)` | The item (behaves as a native value) |
| `doc.keys()` / `.values()` / `.items()` | Dict views |
| `doc.unwrap()` | Nested plain `dict`/`list`/`str`/`int`/… |
| `doc.value` | Plain-ish `dict` of the container |
| `doc.item("key")` | The raw `Item` object, with `.trivia` |
| `doc.last_item()` | Last item in the container |
| `item.trivia.comment` | The trailing comment text |

**Example:**

```python
import tomlkit

doc = tomlkit.parse('name = "app" # the app\nport = 8080\ntags = ["x", "y"]\n')

print(doc["name"].upper())            # APP  — String is a str
print(doc["port"] + 1)                # 8081 — Integer is an int
print(doc["tags"][0])                 # x    — Array is a list

print(doc.item("name").trivia.comment)  # '# the app'

plain = doc.unwrap()
print(type(plain), plain)             # <class 'dict'> {'name': 'app', ...}
```

## 5. Editing an Existing Document

**Description.** Mutating a parsed document is the core use case. Assignment replaces a value in
place and keeps that line's comment and spacing. `add`/`append` add a *new* key (`append` raises
`KeyAlreadyPresent` on a duplicate; `add` accepts comments and whitespace objects too).
`update`, `pop`, `setdefault`, `popitem`, and `clear` behave as on `dict`; `remove(key)` deletes
by key and returns the container for chaining.

| Method | Behaviour |
|---|---|
| `doc[key] = value` | Set or replace; preserves an existing line's trivia |
| `doc.add(key, value)` / `doc.add(comment_or_ws)` | Append a new key, comment, or blank line |
| `doc.append(key, value)` | Append a new key; raises `KeyAlreadyPresent` if it exists |
| `doc.update(mapping)` | Bulk set |
| `doc.pop(key[, default])` | Remove and return |
| `doc.remove(key)` | Remove, return the container |
| `doc.setdefault(key, default)` | Insert if missing, return current value |
| `doc.clear()` | Empty the container |
| `doc.copy()` | Shallow copy |

**Example:**

```python
import tomlkit

doc = tomlkit.parse("""# service config
host = "localhost"   # dev only
port = 8080
""")

doc["host"] = "0.0.0.0"          # comment on that line is kept
doc.add("debug", False)          # appended at the end
doc.setdefault("timeout", 30)
doc.remove("port")

print(tomlkit.dumps(doc))
```

```toml
# service config
host = "0.0.0.0"   # dev only
debug = false
timeout = 30
```

## 6. Building a Document From Scratch

**Description.** When there is no source file, compose the document out of constructors.
`document()` gives the root container; `table()` a `[section]`; `inline_table()` a `{a = 1}`
value; `aot()` an array of tables; `array()` a `[...]`. You can also assign ordinary Python
values and let tomlkit convert them: dicts become tables, lists of dicts become arrays of tables.

| Constructor | Produces |
|---|---|
| `document()` | `TOMLDocument` (root) |
| `table(is_super_table=None)` | `[section]` |
| `inline_table()` | `{ key = value }` |
| `aot()` | `[[section]]` repeated |
| `array(raw="[]")` | `[1, 2, 3]` |

**Example:**

```python
import tomlkit
from tomlkit import aot, array, document, inline_table, table

doc = document()
doc["name"] = "app"

db = table()
db["host"] = "localhost"
db["port"] = 5432
db["point"] = inline_table()
db["point"].update({"x": 1, "y": 2})
doc["database"] = db

products = aot()
for n in ("a", "b"):
    t = table()
    t["name"] = n
    products.append(t)
doc["products"] = products

doc["servers"] = [{"ip": "10.0.0.1"}, {"ip": "10.0.0.2"}]   # auto-converted to an AoT

print(tomlkit.dumps(doc))
```

```toml
name = "app"

[database]
host = "localhost"
port = 5432
point = {x = 1, y = 2}

[[products]]
name = "a"

[[products]]
name = "b"

[[servers]]
ip = "10.0.0.1"

[[servers]]
ip = "10.0.0.2"
```

## 7. Tables, Nesting & Arrays of Tables

**Description.** Nest tables by appending a `Table` into another `Table`. If a parent contains
only sub-tables, tomlkit collapses it into dotted header form (`[parent.child]`) automatically;
`table(True)` forces that *super table* behaviour explicitly. Arrays of tables (`[[x]]`) are
`AoT` objects and support list operations (`append`, `insert`, `pop`, `extend`, indexing).
When a file defines the same table in non-contiguous places, tomlkit hands you an
`OutOfOrderTableProxy` that reads and writes as one table while leaving the file layout alone.

| Concept | API |
|---|---|
| Sub-table | `parent.append("child", table())` |
| Super table | `table(True)` — renders as `[parent.child]` only |
| Array of tables | `aot()`, then `.append(table())` |
| AoT element check | `tbl.is_aot_element()` |
| Split table in source | `OutOfOrderTableProxy` (transparent) |
| Detach display name cache | `tbl.invalidate_display_name()` |

**Example:**

```python
import tomlkit
from tomlkit import document, table

doc = document()
parent = table()
child = table()
child["k"] = 1
parent.append("child", child)
doc.append("parent", parent)

print(tomlkit.dumps(doc))
# [parent.child]
# k = 1

# Out-of-order tables
doc2 = tomlkit.parse("[a.b]\nx = 1\n[c]\ny = 2\n[a]\nz = 3\n")
print(type(doc2["a"]).__name__)     # OutOfOrderTableProxy
doc2["a"]["w"] = 4                  # written into the [a] block, file order untouched
print(tomlkit.dumps(doc2))
```

```toml
[a.b]
x = 1
[c]
y = 2
[a]
z = 3
w = 4
```

## 8. Arrays

**Description.** `Array` subclasses `list`, so all list methods apply and edits keep the existing
layout — appending to a multi-line array adds a properly indented line. `multiline(True)` switches
an array to one-item-per-line; `add_line(*values, indent="    ", comment=None, add_comma=True,
newline=True)` gives precise control over hand-built multi-line arrays, and a final
`add_line(indent="")` emits the closing line.

| Method | Purpose |
|---|---|
| `array(raw="[]")` | Construct, optionally from raw TOML text |
| `arr.append/extend/insert/pop/remove/sort/reverse` | Standard list ops |
| `arr.multiline(True/False)` | Toggle one-value-per-line rendering |
| `arr.add_line(*vals, indent=…, comment=…, newline=…)` | Append a formatted line |
| `arr.comment("text")` | Set a trailing comment on the array |

**Example:**

```python
import tomlkit
from tomlkit import array, document

# Editing preserves the source layout
doc = tomlkit.parse("x = [\n  1,\n  2,\n]\n")
doc["x"].append(3)
print(tomlkit.dumps(doc))
# x = [
#   1,
#   2,
#   3,
# ]

a = array()
a.add_line(1, 2, newline=True)
a.add_line(3)
a.add_line(indent="")          # closing bracket on its own line
d = document()
d["a"] = a

b = array()
b.extend([1, 2, 3])
b.multiline(True)
d["b"] = b
print(tomlkit.dumps(d))
```

```toml
a = [
    1, 2,
    3,
]
b = [
    1,
    2,
    3,
]
```

## 9. Scalar Value Constructors

**Description.** Use these when you want an item with explicit typing or formatting rather than
letting tomlkit infer it from a Python value. `string()` is the most useful: it controls literal
(`'...'`), multi-line (`"""..."""`), and escaping behaviour. Note that the numeric and temporal
constructors convert their argument through the corresponding Python type, so an exotic literal
(`0x1f`, `1.0e3`) is normalized — use `value()` or `parse()` to keep the literal exactly as written.

| Function | Produces | Notes |
|---|---|---|
| `string(raw, *, literal=False, multiline=False, escape=True)` | `String` | Quote-style control |
| `integer(raw: str \| int)` | `Integer` | `raw` goes through `int()` — decimal only |
| `float_(raw: str \| float)` | `Float` | Goes through `float()`; `1.0e3` → `1000.0` |
| `boolean(raw: str \| bool)` | `Bool` | `"true"` / `"false"` / `True` / `False` |
| `date(raw: str)` | `Date` | `"1979-05-27"` |
| `time(raw: str)` | `Time` | `"07:32:00"` |
| `datetime(raw: str)` | `DateTime` | `"1979-05-27T07:32:00Z"` |
| `item(value, _sort_keys=False)` | Any `Item` | Convert an arbitrary Python object |

**Example:**

```python
import tomlkit
from tomlkit import boolean, date, document, float_, item, string, value

doc = document()
doc["path"] = string(r"C:\Users\app", literal=True)     # 'C:\Users\app'
doc["bio"] = string("line1\nline2", multiline=True)     # """line1\nline2"""
doc["quoted"] = string('he said "hi"')                  # "he said \"hi\""
doc["enabled"] = boolean("true")
doc["ratio"] = float_(0.75)
doc["born"] = date("1979-05-27")
doc["mask"] = value("0x1f")                             # literal 0x1f preserved
doc["nested"] = item({"b": 1, "a": 2}, _sort_keys=True)

print(tomlkit.dumps(doc))
```

```toml
path = 'C:\Users\app'
bio = """line1
line2"""
quoted = "he said \"hi\""
enabled = true
ratio = 0.75
born = 1979-05-27
mask = 0x1f

[nested]
a = 2
b = 1
```

## 10. Keys & Raw Fragments

**Description.** These low-level helpers parse or construct the pieces of a TOML line. `key()`
builds a key — pass an iterable of strings for a dotted key (`a.b.c`). `value()` parses a single
TOML *value* expression and returns the matching item, preserving its literal form.
`key_value()` parses a whole `key = value` line into a `(Key, Item)` pair.

| Function | Purpose |
|---|---|
| `key(k: str \| Iterable[str])` | Build a simple or dotted `Key` |
| `value(raw: str)` | Parse a TOML value expression |
| `key_value(src: str)` | Parse a `key = value` line → `(Key, Item)` |

**Example:**

```python
import tomlkit
from tomlkit import document, integer, key, key_value, value

doc = document()
doc.append(key(["tool", "app", "version"]), integer(3))   # dotted key

print(value("[1, 2]"))                    # [1, 2]
print(type(value("1979-05-27")).__name__) # Date

k, v = key_value('name = "app"')
print(k, repr(v))                         # name 'app'

print(tomlkit.dumps(doc))                 # tool.app.version = 3
```

## 11. Comments, Whitespace & Indentation

**Description.** Formatting is first-class. `comment()` creates a standalone comment line and
`nl()` / `ws()` create blank lines and arbitrary whitespace — add them to a container with
`.add()`. Every item also carries *trivia*: `item.comment("text")` attaches a trailing comment,
`item.indent(n)` indents the item (and, for a table, its header), and `item.trivia.comment` reads
the existing comment back.

| API | Effect |
|---|---|
| `comment("text")` | Standalone `# text` line |
| `nl()` | A single blank line |
| `ws(" \n\n")` | Arbitrary raw whitespace |
| `item.comment("text")` | Trailing comment on that item/table |
| `item.indent(n)` | Indent by `n` spaces |
| `doc.item(k).trivia.comment` | Read the comment text |

**Example:**

```python
import tomlkit
from tomlkit import comment, document, item, nl, table

doc = document()
doc.add(comment("Database settings"))
doc.add(nl())

db = table()
db.add(comment("connection"))
db["host"] = "localhost"
db["port"] = 5432
db.comment("primary node")
doc["db"] = db

ports = item([80, 443])
ports.comment("public ports")
doc["ports"] = ports

print(tomlkit.dumps(doc))
```

```toml
# Database settings

ports = [80, 443] # public ports

[db] # primary node
# connection
host = "localhost"
port = 5432
```

## 12. Custom Types (Encoders)

**Description.** To serialize objects tomlkit does not know, register an encoder: a callable that
takes an object and returns a tomlkit `Item`, raising `TypeError` for anything it does not handle.
`register_encoder` works as a decorator and returns the function, so it can be unregistered later.
Encoders are consulted in reverse registration order; if none matches, tomlkit raises
`ConvertError`.

| Function | Purpose |
|---|---|
| `register_encoder(fn)` | Add an encoder (usable as a decorator) |
| `unregister_encoder(fn)` | Remove a previously registered encoder |

**Example:**

```python
import tomlkit
from tomlkit import document, item, register_encoder, unregister_encoder

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

@register_encoder
def encode_point(obj):
    if isinstance(obj, Point):
        return item({"x": obj.x, "y": obj.y})
    raise TypeError("not supported")

doc = document()
doc["p"] = Point(1, 2)
print(tomlkit.dumps(doc))
# [p]
# x = 1
# y = 2

unregister_encoder(encode_point)
# document()["p"] = Point(1, 2)  ->  ConvertError
```

## 13. Exceptions & Error Handling

**Description.** All exceptions live in `tomlkit.exceptions` and derive from `TOMLKitError`.
Syntax problems raise a `ParseError` subclass exposing `.line` and `.col`; lookup and mutation
problems raise `NonExistentKey` (a `KeyError`) or `KeyAlreadyPresent`. Catch `TOMLKitError` to
cover everything the library can throw.

| Exception | Raised when |
|---|---|
| `TOMLKitError` | Base class for all of the below |
| `ParseError` | Any syntax error; has `.line`, `.col` |
| `UnexpectedCharError`, `UnexpectedEofError` | Malformed or truncated input |
| `EmptyKeyError`, `EmptyTableNameError` | Missing key or table name |
| `InvalidNumberError`, `InvalidDateError`, `InvalidTimeError`, `InvalidDateTimeError` | Bad literals |
| `InvalidStringError`, `InvalidCharInStringError`, `InvalidControlChar`, `InvalidUnicodeValueError` | Bad string content |
| `MixedArrayTypesError` | Mixed-type array (pre-1.0 rule) |
| `NonExistentKey` | Missing key on lookup (subclass of `KeyError`) |
| `KeyAlreadyPresent` | `append()` of a key that already exists |
| `ConvertError` | No encoder for a Python object |
| `InternalParserError` | Library bug — report it |

**Example:**

```python
import tomlkit
from tomlkit.exceptions import KeyAlreadyPresent, NonExistentKey, ParseError

try:
    tomlkit.parse("a = = 1")
except ParseError as e:
    print(f"{e} (line {e.line}, col {e.col})")
    # Unexpected character: '=' at line 1 col 4 (line 1, col 4)

doc = tomlkit.parse("a = 1")

try:
    doc["b"]
except NonExistentKey as e:
    print(e)              # 'Key "b" does not exist.'

try:
    doc.append("a", 2)
except KeyAlreadyPresent as e:
    print(e)              # Key "a" already exists.
```

## 14. Type Reference

**Description.** Mapping between TOML syntax, the tomlkit class you get back, and the Python type
it subclasses. Because the item classes inherit from native types, you rarely need to convert
anything explicitly.

| TOML | tomlkit class | Subclasses | Constructor |
|---|---|---|---|
| `"text"` | `String` | `str` | `string()` |
| `42`, `0x1f` | `Integer` | `int` | `integer()` |
| `1.5` | `Float` | `float` | `float_()` |
| `true` | `Bool` | (int-backed) | `boolean()` |
| `1979-05-27T07:32:00Z` | `DateTime` | `datetime.datetime` | `datetime()` |
| `1979-05-27` | `Date` | `datetime.date` | `date()` |
| `07:32:00` | `Time` | `datetime.time` | `time()` |
| `[1, 2]` | `Array` | `list` | `array()` |
| `{a = 1}` | `InlineTable` | `dict` | `inline_table()` |
| `[section]` | `Table` | `dict` | `table()` |
| `[[section]]` | `AoT` | `list` | `aot()` |
| whole file | `TOMLDocument` | `dict` (`Container`) | `document()` |
| `# text` | `Comment` | — | `comment()` |
| blank line | `Whitespace` | — | `nl()`, `ws()` |

**Example:**

```python
import tomlkit

doc = tomlkit.parse('s = "x"\ni = 1\nf = 1.5\na = [1]\nt = {x = 1}\n')

for k, v in doc.items():
    print(k, type(v).__name__)
# s String
# i Integer
# f Float
# a Array
# t InlineTable

print(isinstance(doc["s"], str), isinstance(doc["a"], list), isinstance(doc, dict))
# True True True
```

## 15. Recipes

**Description.** Practical end-to-end patterns assembled from the sections above.

**Bump a version in `pyproject.toml` without disturbing the file:**

```python
import tomlkit

path = "pyproject.toml"
with open(path, encoding="utf-8") as f:
    doc = tomlkit.load(f)

major, minor, patch = doc["project"]["version"].split(".")
doc["project"]["version"] = f"{major}.{minor}.{int(patch) + 1}"

with open(path, "w", encoding="utf-8") as f:
    tomlkit.dump(doc, f)
```

**Append a dependency to a multi-line array:**

```python
import tomlkit

doc = tomlkit.parse("""[project]
dependencies = [
    "requests>=2",
]
""")
doc["project"]["dependencies"].append("httpx>=0.27")
print(tomlkit.dumps(doc))
# dependencies = [
#     "requests>=2",
#     "httpx>=0.27",
# ]
```

**Add a new commented section to an existing config:**

```python
import tomlkit
from tomlkit import comment, nl, table

doc = tomlkit.parse("[server]\nport = 80\n")

cache = table()
cache.add(comment("TTL in seconds"))
cache["ttl"] = 300
doc.add(nl())
doc["cache"] = cache
print(tomlkit.dumps(doc))
```

**Convert TOML to JSON (drop all formatting):**

```python
import json, tomlkit

doc = tomlkit.parse(open("config.toml", encoding="utf-8").read())
print(json.dumps(doc.unwrap(), indent=2, default=str))
```

**Safely read a nested value with defaults:**

```python
timeout = doc.get("server", {}).get("timeout", 30)
```

## 16. Gotchas & Limitations

**Description.** Behaviours that surprise people, with the workaround for each.

| Gotcha | Detail / workaround |
|---|---|
| Booleans read back as plain `bool` | `doc["flag"]` is a native `bool`, not a `Bool` item. To reach its comment use `doc.item("flag")`. |
| `integer("0x1f")` fails | The `raw` argument passes through `int()`. Use `value("0x1f")` or parse the line instead. |
| `float_("1.0e3")` renders `1000.0` | Numeric constructors normalize through Python types. Use `value("1.0e3")` to keep the literal. |
| `append()` on an existing key raises | Use `doc[key] = …` or `doc.update()` to overwrite; `append` is strictly for new keys. |
| `unwrap()` ordering may differ | Rely on `dumps()` for output order; `unwrap()` is for data, not layout. |
| Nested tables collapse to dotted headers | A parent holding only sub-tables renders as `[parent.child]`. Give the parent a scalar key, or use `table(is_super_table=False)`, to force a separate `[parent]` header. |
| Repeated table headers | Produce an `OutOfOrderTableProxy`, not a `Table`. It reads and writes like a table; `isinstance(x, Table)` checks will fail. |
| `sort_keys=True` discards ordering | It also reorders sections; do not use it on files a human maintains. |
| Plain dicts get default formatting | `dumps({...})` cannot invent comments or layout — only round-tripped documents preserve style. |
| Performance | The formatting model makes tomlkit slower than `tomllib`. For read-only loading of large files, prefer `tomllib` (stdlib, 3.11+). |

**Example — choosing the right library:**

```python
# Read-only, speed matters -> stdlib
import tomllib
with open("config.toml", "rb") as f:
    data = tomllib.load(f)          # plain dict, no formatting retained

# Editing a file a human owns -> tomlkit
import tomlkit
with open("config.toml", encoding="utf-8") as f:
    doc = tomlkit.load(f)
doc["version"] = "2.0"
with open("config.toml", "w", encoding="utf-8") as f:
    tomlkit.dump(doc, f)            # comments and layout intact
```
